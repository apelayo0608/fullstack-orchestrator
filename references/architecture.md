# Stack and architecture

Default stack: **React + Vite SPA** (TypeScript, Tailwind CSS v4, Motion, Zustand, TanStack Query) → **Vite proxy** → **Express 5** API (TypeScript, Clean Architecture) → **PostgreSQL**.
Use **Next.js** only when the user asks for it (SSR/SEO). Express stays the API either way (see §6).

## 1. Repository layout

```
apps/
  web/                      React + Vite (or Next.js)
  api/                      Express API
packages/                   optional shared code (e.g. zod schemas shared by web and api)
package.json                npm/pnpm workspaces; scripts: dev, build, test, lint, typecheck
.env.example                every env var with placeholders; real .env files are git-ignored
```
Keep the user's existing layout when one exists.

## 2. API: Clean Architecture

```
apps/api/src/
  domain/            entities, value objects, domain errors, repository interfaces (ports)
  application/       use cases, policies (ownership), service ports (FieldEncryptor, Mailer, Totp, OtpCrypto)
  infrastructure/    pg repositories, crypto (AES-GCM, key ring, blind index, TOTP), mailer, config
  interface/http/    express app, routes, zod schemas, middleware, error handler
  main.ts            composition root: load config → build pool, key ring, repos → use cases → createApp → listen
apps/api/db/migrations/  plain SQL, numbered (001_init.sql, ...)
apps/api/tests/          vitest + supertest against a real disposable Postgres
```

**Dependency rule:** `domain` imports nothing from other layers. `application` imports only `domain` and its own ports. `infrastructure` and `interface` implement ports and depend inward. Only `main.ts` knows every concrete class. Keep DI manual: factory functions and constructor arguments, no container.

- **Use cases** are plain functions or objects taking `(actor, input)`. They hold business rules and ownership policy and know nothing about HTTP.
- **Routes** parse and validate input (zod), call one use case and map the result to a response DTO. No SQL and no business rules in routes.
- **Repositories** own SQL, owner scoping and field encryption. They return domain entities.
- **Errors:** throw domain errors (`NotFoundError`, `ValidationError`, `ForbiddenError`, `UnauthorizedError`); the error handler maps them to HTTP.

### TypeScript and runtime
`"type": "module"`, Node ≥ 22. Relative imports use the `.ts` extension, so the code runs natively in dev (`node --watch src/main.ts`) and builds with `tsc`:
```jsonc
{
  "compilerOptions": {
    "target": "ES2023", "module": "NodeNext", "moduleResolution": "NodeNext",
    "strict": true, "noUncheckedIndexedAccess": true,
    "verbatimModuleSyntax": true, "erasableSyntaxOnly": true,
    "rewriteRelativeImportExtensions": true,
    "rootDir": "src", "outDir": "dist", "skipLibCheck": true
  }
}
```
`erasableSyntaxOnly` rules out enums, namespaces (except `declare`) and constructor parameter properties. Use union types, plain objects and explicit fields.

Core packages: `express@5` (async errors propagate natively), `zod@4`, `pg`, `helmet`, `express-rate-limit`, `cookie-parser`, `argon2`, `uuid` (v7), `vitest`, `supertest`.

## 3. PostgreSQL
- Plain SQL migrations, numbered and forward-only, applied by a small runner or `node-pg-migrate`. Never edit an applied migration.
- `uuid` primary keys generated by the app (UUIDv7), `timestamptz` everywhere, `NOT NULL` by default, foreign keys with explicit `ON DELETE`.
- Every user-owned table: `owner_id uuid NOT NULL REFERENCES users(id)` plus an index starting with `owner_id`.
- Encrypted columns are suffixed `_enc` (text envelope); blind indexes are suffixed `_bidx`.
- Use `pg.Pool` with parameterized queries only. Use transactions (`BEGIN … COMMIT` on one client) for multi-statement writes.
- Template: `templates/server/db/migrations/001_init.sql`.

## 4. Web client (React + Vite)

```
apps/web/src/
  app/               providers (QueryClientProvider, router), routes, layout
  features/<name>/   api hooks (TanStack Query), components, feature-local state
  shared/lib/        api-client, query-client (+ query key factories)
  shared/stores/     Zustand stores (UI state only)
  shared/ui/         reusable components, animation primitives
  index.css          Tailwind entry
  vite-env.d.ts      /// <reference types="vite/client" />
```
The `@/` import alias is set in `vite.config.ts` (`resolve.alias`) and in tsconfig as `"paths": { "@/*": ["./src/*"] }` with `"moduleResolution": "bundler"`. Do not set `baseUrl`, because TypeScript 7 removed it.

### 4.1 Vite proxy (`templates/client/vite.config.ts`)
`server.proxy['/api'] → http://localhost:4000`. The browser only talks to `:5173`, so the session cookie is first-party, no CORS is needed in dev, and the client always calls relative `/api/...`. In production, a reverse proxy (nginx, Caddy, platform routing) serves the SPA and forwards `/api` to Express on the same origin.

### 4.2 State: TanStack Query vs Zustand
- **TanStack Query owns all server state:** fetching, caching, mutations, optimistic updates, invalidation. Use query key factories (`queryKeys.notes.detail(id)`). After a mutation, invalidate the feature's `all` key or update the cache precisely.
- **Zustand owns client-only UI state:** theme, sidebar, modal open state, multi-step form drafts. Never copy server data into Zustand, and never store tokens, secrets or PII there.
- Templates: `shared/lib/query-client.ts`, `shared/stores/ui-store.ts`, `features/auth/*`.

### 4.3 API client (`templates/client/src/shared/lib/api-client.ts`)
`fetch('/api' + path)` with `credentials: 'same-origin'`, JSON in and out, a typed `ApiError` (status, code, issues), and a global 401 handler that clears the query cache and routes to login.

### 4.4 Tailwind CSS v4
`@tailwindcss/vite` plugin and `@import "tailwindcss"` in `index.css`. Design tokens go in `@theme` (colors in OKLCH, fonts, easing). Class-based dark mode uses `@custom-variant dark`. Compose UI from small components; avoid long one-off class strings repeated across files (extract a component instead). Use `clsx` + `tailwind-merge` for conditional classes.

### 4.5 Animations
- **Motion** (`motion/react`) for enter/exit, layout and list animations (`AnimatePresence`, `layout`). Use Tailwind `transition-*` for hover and focus micro-interactions.
- Animate only `transform` and `opacity`. Keep UI transitions at 150–300 ms.
- Respect `prefers-reduced-motion` (`useReducedMotion`, plus the CSS fallback in `index.css`).
- Template: `templates/client/src/shared/ui/animated-page.tsx`.

### 4.6 Forms and UX
`react-hook-form` + `@hookform/resolvers/zod`, reusing the same zod schemas as the API where practical. Every data view has loading, error and empty states. Forms show field-level errors from `ApiError.issues`. Use accessible labels and visible focus states.

## 5. Testing and quality gates
- API: vitest + supertest against a real Postgres (Testcontainers or a per-run database). IDOR suite per resource. Unit tests for crypto, TOTP and use cases.
- Web: vitest + Testing Library for components and hooks. Add Playwright for critical flows (login + MFA) when requested.
- Every task must pass `typecheck`, `lint` (ESLint + typescript-eslint), and `test` before the developer reports done.

## 6. Next.js variant (only on request)
- Next.js App Router renders the UI. Express remains the API; Next does not talk to Postgres directly.
- Replace the Vite proxy with `rewrites()` in `next.config.ts`: `{ source: '/api/:path*', destination: 'http://localhost:4000/api/:path*' }`, so the cookie stays first-party.
- TanStack Query and Zustand live in client components (`'use client'` providers). Server components may fetch through the same `/api` with the incoming cookie forwarded.
- Everything else in this file and in `security.md` applies unchanged.
